# Audit Finding Ledger

This is a maintainer evidence ledger, not user documentation. It records audit
findings, their required proof, and the evidence gathered so far, and it is
retained as historical evidence as well as an active backlog. Each row's status
and `Updated` date describe the repository at that date; later work is recorded
by updating the row, never by rewriting history. Rows that are still `open`,
`fixed_pending_regression`, or `blocked` are genuinely unresolved backlog, not
stale entries. The `Target` column names phases of the audit roadmap (Phase 7 is
the owner-directed 2026-09 capability expansion), which are separate from the
product roadmap phases in [the program](./coding-agents-program.md#20-roadmap).
Finding IDs are stable and are never reused or renumbered. A finding is not
closed by an implementation alone; its required regression and verification
evidence must also be recorded here.

The ledger describes repository work only. It does not record credentials,
account data, private filesystem paths, raw model output, or external secrets.

## Status vocabulary

- `open`: verified or seeded work that has not been closed.
- `in_progress`: implementation is active in the current phase.
- `fixed_pending_regression`: the source fix exists but required proof has not passed.
- `verified_repository`: repository-owned regression and required local checks passed.
- `verified_live`: direct host evidence passed in addition to repository proof.
- `blocked`: a named external or environmental prerequisite prevents progress.
- `deferred_with_evidence`: an explicit decision records why implementation is not currently justified.
- `not_reproduced`: inspection or attempted reproduction disproved the seeded finding.
